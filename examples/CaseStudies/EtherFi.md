## Core Components

Nama: eETH (Liquid Staking Token)
Fungsi: ERC-20 rebasing token mewakili staked ETH + auto-compounding staking reward + restaking reward; supply bertambah via rebase setiap epoch
Status: Live di Ethereum Mainnet sejak 2023
Sources: (HIGH) [Etherscan eETH, https://etherscan.io/token/0x35fA164735182de50811E8e2E824cFb9B6118ac2; EtherFi Docs eETH, https://docs.ether.fi/tokens/eeth]

Nama: weETH (Wrapped eETH)
Fungsi: ERC-20 non-rebasing wrapper untuk eETH — 1 weETH = 1 eETH (fixed balance), nilai meningkat via price appreciation; kompatibel DeFi dan cross-chain bridge
Status: Live di Ethereum Mainnet + 10+ L2/L1
Sources: (HIGH) [Etherscan weETH, https://etherscan.io/token/0xCd5fE23C85820F7B72D0926FC9b05b43E359b7ee; EtherFi Docs weETH, https://docs.ether.fi/tokens/weeth]

Nama: ETHFI Token
Fungsi: ERC-20 governance token — voting DAO, fee accrual (fee switch), incentive alignment
Status: Live sejak TGE 18 Maret 2024
Sources: (HIGH) [Etherscan ETHFI, https://etherscan.io/token/0xfe0c30065b384f05761f15d0cc899d4f9f9cc0eb; CoinMarketCap ETHFI, https://coinmarketcap.com/currencies/etherfi/]

Nama: EtherFi Staking Contract (DepositContract / StakeManager)
Fungsi: Menerima ETH deposit, mint eETH, mengelola validator delegation ke node operator, mengakumulasi reward, handle withdraw request
Status: Live di Ethereum Mainnet (V1 2023, V2 2023-11)
Sources: (HIGH) [EtherFi GitHub Contracts, https://github.com/etherfi-protocol/contracts; EtherFi Docs Staking, https://docs.ether.fi/staking]

Nama: weETH Wrapper Contract (WETH9-style / eETHWrapper)
Fungsi: Mint/burn weETH terhadap eETH deposit/withdraw; handle rebase accounting via share/price mechanism
Status: Live di Ethereum Mainnet + multi-chain deployment

## Known Technical Limitations

eETH rebasing mechanism tidak kompatibel dengan sebagian besar DeFi protocol (AMM, lending) — memerlukan weETH wrapper untuk composability (HIGH) [EtherFi Docs eETH vs weETH, https://docs.ether.fi/tokens/eeth; https://docs.ether.fi/tokens/weeth]
weETH bridging mengandalkan canonical bridge (7 hari withdrawal untuk Optimism/Arbitrum) atau third-party bridge (LayerZero/Wormhole) dengan trust assumptions tambahan — finality dan security bervariasi per bridge (HIGH) [EtherFi Docs Bridging, https://docs.ether.fi/bridging; Optimism Bridge Docs, https://docs.optimism.io/bridge; Arbitrum Bridge Docs, https://docs.arbitrum.io/bridging]
EigenLayer withdrawal queue — withdraw dari restaking memerlukan EigenLayer withdrawal period (7 hari escrow + challenge period) — likuiditas eETH/weETH terkunci selama periode ini (HIGH) [EigenLayer Docs Withdrawal, https://docs.eigenlayer.xyz/withdrawal; EtherFi Docs Restaking, https://docs.ether.fi/restaking]
Symbiotic withdrawal mechanics — mirip EigenLayer, memiliki withdrawal queue dan slashing risk (MEDIUM) [Symbiotic Docs, https://docs.symbiotic.fi]
Ultra Light Node operator permissionless — tidak ada KYC/reputation requirement; staker bear risk operator performance/slashing (MEDIUM) [EtherFi Docs ULN, https://docs.ether.fi/ultra-light-node]
Cross-chain weETH supply tidak sinkron real-time — bridge latency dan finality beda per chain menyebabkan temporary supply mismatch (MEDIUM) [EtherFi Docs Multi-chain, https://docs.ether.fi]
Vault risk parameter (max allocation per AVS, slashing threshold) — hardcoded/upgradeable via governance; tidak ada automated risk engine on-chain (MEDIUM) [EtherFi Docs Vaults, https://docs.ether.fi/vaults]
EtherFi Cash kartu kredit — bergantung pada off-chain payment processor (Visa/Mastercard network) dan custodian stablecoin; bukan fully on-chain (MEDIUM) [EtherFi Cash Site, https://cash.ether.fi]
Governance timelock minimal 2 hari — memperlambat emergency response untuk critical bug (MEDIUM) [EtherFi Docs Governance, https://docs.ether.fi/governance]
Smart contract upgrade via UUPS proxy — upgradeability risk (storage collision, initialization bypass) dimitigasi via OpenZeppelin patterns tapi tetap ada risk (MEDIUM) [OpenZeppelin UUPS Security, https://docs.openzeppelin.com/contracts/4.x/upgradeable#security-considerations]

## Ecosystem Risks

Risk: Single Restaking Layer Dependency (EigenLayer)
Type: Protocol Dependency
Description: Sebagian besar restaking yield dan TVL bergantung pada EigenLayer — jika EigenLayer mengalami exploit, slashing massal, atau regulatory action, EtherFi terpengaruh langsung
Sources: https://docs.eigenlayer.xyz, https://docs.ether.fi/restaking, https://defillama.com/protocol/etherfi

Risk: Alternative Restaking Layer Dependency (Symbiotic)
Type: Protocol Dependency
Description: Symbiotic sebagai layer kedua — risiko serupa: exploit, slashing, regulatory, atau failure to attract AVS
Sources: https://docs.symbiotic.fi, https://docs.ether.fi

Risk: Bridge Dependency (Canonical + Third-Party)
Type: Bridge Dependency
Description: weETH cross-chain bergantung pada canonical bridge (7 hari withdrawal Optimism/Arbitrum) dan third-party bridge (LayerZero/Wormhole/Hyperlane) dengan trust assumptions berbeda — bridge hack = loss of funds cross-chain
Sources: https://docs.ether.fi/bridging, https://docs.layerzero.network, https://docs.wormhole.com, https://docs.hyperlane.xyz

Risk: Oracle Dependency (Chainlink)
Type: Oracle Dependency
Description: Vault liquidation dan risk management bergantung pada Chainlink Price Feeds — oracle manipulation atau downtime dapat trigger liquidation palsu atau gagal liquidate
Sources: https://docs.chain.link, https://docs.ether.fi/vaults

Risk: Chain Dependency (Ethereum L1)
Type: Chain Dependency
Description: Semua core contracts di Ethereum L1 — L1 congestion, gas spike, atau consensus failure mempengaruhi seluruh protokol
Sources: https://ethereum.org, https://docs.ether.fi

Risk: Centralized Exchange Dependency (CEX Liquidity)
Type: Liquidity Dependency
Description: ETHFI token liquidity primer di Binance, Coinbase, OKX, Bybit, Gate.io, KuCoin — delisting atau regulatory action pada CEX mengurangi liquidity drastis
Sources: https://www.binance.com/en/trade/ETHFI_USDT, https://www.coinbase.com/price/etherfi, https://www.okx.com/trade/ETHFI-USDT, https://www.bybit.com/trade/spot/ETHFI/USDT, https://www.gate.io/trade/ETHFI_USDT, https://www.kucoin.com/trade/ETHFI-USDT

Risk: Cloud Hosting Dependency (Vercel)
Type: Cloud Dependency
Description: Frontend hosting di Vercel — outage Vercel = tidak bisa akses app.ether.fi dan cash.ether.fi (smart contract tetap accessible via Etherscan/CLI)
Sources: https://vercel.com/docs, https://app.ether.fi, https://cash.ether.fi

Risk: GitHub Dependency
Type: Infrastructure Dependency
Description: Source code, CI/CD, issue tracking di GitHub — outage atau policy change GitHub mengganggu development dan deployment
Sources: https://github.com/etherfi-protocol, https://github.com/etherfi-protocol/contracts/actions

Risk: Permissionless Operator Set (ULN)
Type: Centralization Risk (inverse — over-decentralization risk)
Description: Operator permissionless tanpa KYC/reputation — staker bear risk operator performance, slashing, dan MEV extraction tanpa recourse
Sources: https://docs.ether.fi/ultra-light-node, https://blog.ether.fi

Risk: Governance Timelock Delay
Type: Centralization Risk (governance responsiveness)
Description: Minimal 2 hari timelock untuk emergency response — critical bug/exploit memerlukan PAUSER_ROLE (multi-sig/DAO) untuk pause, tapi upgrade butuh timelock
Sources: https://docs.ether.fi/governance, https://snapshot.org/#/etherfi.eth

Risk: Smart Contract Upgradeability (UUPS Proxy)
Type: Technical Risk
Description: UUPS proxy upgradeability risk — storage collision, initialization bypass, admin key compromise (UPGRADER_ROLE)
Sources: https://docs.openzeppelin.com/contracts/4.x/upgradeable#security-considerations, https://github.com/etherfi-protocol/contracts

Lessons Learned

1. Dual-layer restaking architecture (EigenLayer + Symbiotic) memberikan risk diversification yang nyata tapi menambah operational complexity 2x — perlu unified risk engine dari day one.
2. Exchange-affiliated VC funding adalah cheat code untuk CEX listing dan liquidity tapi menciptakan platform dependency risk yang sulit di-eliminate.
3. Rebase token + non-rebase wrapper pattern adalah industry standard untuk LST DeFi composability — EtherFi execute early dan benar.
4. Progressive decentralization via DAO dengan timelock bekerja tapi emergency response memerlukan PAUSER_ROLE multi-sig yang centralized — trade-off security vs responsiveness.
5. Multi-chain deployment speed (11 chain/2 bulan) capture incentives tapi bridge risk fragmentation memerlukan dedicated monitoring infrastructure.
6. Financial transparency opacity mungkin melindungi strategic flexibility tapi jadi blocker utama institutional adoption — DeFi transparency standard naik.
7. Permissionless operator network achieve desentralisasi tapi socialize slashing risk ke staker tanpa protection — institutional product (Vaults) perlu managed operator set.
8. Comprehensive audit program (8 firms) effective untuk security tapi tidak substitute untuk formal verification pada critical contracts.
9. Product suite multi-segment (retail, institutional, operator, tradfi) diversify revenue tapi stretch team focus — each product perlu dedicated squad.
10. Bridge abstraction (canonical + third-party) memberikan user choice tapi menciptakan fragmented liquidity dan supply tracking nightmare — perlu canonical bridge preference sebagai default.
