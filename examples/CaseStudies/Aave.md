## Technology Intelligence
_ref: `docs/Ontology/Technology.md`_

TECHNOLOGY INTELLIGENCE DATASET — AAVE

System Architecture

V1 (2020): Arsitektur berbasis kontrak terpisah dengan PoolCore sebagai kontrak utama yang menyimpan state seluruh reserve dan aset yang disuplai. PoolAddressesProvider berfungsi sebagai registri global alamat protokol yang immutable. PoolDataProvider melakukan kalkulasi dan menyediakan data untuk Pool contract. V1 menggunakan ETH langsung (bukan WETH) dan posisi pengguna tidak ditokenisasi.

V2 (2020): Peningkatan dari V1 dengan mengganti PoolCore — aset kini dipegang langsung oleh aTokens. Posisi pengguna ditokenisasi melalui aTokens. Memperkenalkan debt tokenization, credit delegation, batch flash loans, collateral swaps, dan fixed & variable borrowing rates.

V3 (2022): Arsitektur modular dengan kontrak inti yang terdiri dari Pool (entry point utama), PoolConfigurator (konfigurasi), ACLManager (registri peran dan izin), PoolAddressesProvider (registri komponen), dan L2Pool (versi teroptimasi untuk rollup). Memperkenalkan isolated liquidity pools dan cross-chain functionality. Protokol di-deploy di 14+ jaringan blockchain.

V4 (2026): Arsitektur modular hub-and-spoke yang memisahkan manajemen likuiditas dari operasi yang berhadapan dengan pengguna dan agunan. Liquidity Hub berfungsi sebagai lapisan settlement pusat yang mengonsolidasikan likuiditas dan akuntansi di seluruh protokol. Spokes adalah modul yang mengimplementasikan peminjaman modular dengan risiko terisolasi. Capital tidak lagi terfragmentasi antar pasar di chain yang sama; semua likuiditas mengalir melalui Liquidity Hubs.

Core Components

Pool (V1-V3): Kontrak entry point utama untuk interaksi pengguna dengan protokol. Mengekspos metode manajemen likuiditas seperti deposit dan borrow.

PoolAddressesProvider: Registri berbagai komponen protokol, termasuk ACLManager dan Pool contracts. Memiliki kemampuan untuk memperbarui pointer atau implementasi kontrak proxy.

PoolConfigurator: Menyediakan metode konfigurasi untuk Pool contract. Fungsi write hanya dapat dipanggil oleh alamat dengan peran sistem yang dikelola oleh ACLManager.

ACLManager (V3): Kontrak registri utama untuk peran dan izin sistem.

L2Pool (V3): Modifikasi kontrak Pool untuk L2 rollup dengan metode yang dioptimalkan gas, menggunakan argumen input terenkripsi byte untuk mengurangi biaya transaksi di rollup.

ATokens: Token penghasil yield yang dicetak dan dibakar saat supply dan withdraw aset ke Aave Pool. Mengimplementasikan standar EIP-20/ERC20.

VariableDebtToken (V3): Token non-transferable yang menghasilkan bunga, merepresentasikan posisi dengan suku bunga variabel.

AaveOracle: Registri oracle reserve untuk mendapatkan harga aset dan mengelola sumber harga.

DefaultReserveInterestRateStrategy: Kontrak yang menyimpan informasi untuk menghitung dan memperbarui suku bunga reserve spesifik.

Liquidity Hub (V4): Kontrak pintar yang memegang likuiditas protokol secara terpusat. Mengelola credit lines, menegakkan parameter risiko, dan beroperasi di bawah kontrol governance.

Spoke (V4): Kontrak pintar yang terhubung ke Hub dan memberlakukan aturan peminjaman spesifik. Pengguna berinteraksi langsung dengan Spokes. Setiap Spoke dapat memiliki jenis agunan, parameter risiko, dan aturan likuidasi sendiri.

Reserves (V4): Unit akuntansi untuk aset spesifik di dalam setiap Spoke. Melacak deposit, pinjaman, pembayaran, dan akrual bunga.

Position Manager (V4): Komponen yang mengelola posisi pengguna, termasuk kontrak gateway.

Access Control (V4): Kontrak yang mengelola kontrol akses.

Config Engine (V4): Mesin konfigurasi untuk pembuatan payload governance.

Consensus Mechanism

N/A — Aave adalah protokol aplikasi yang berjalan di atas blockchain (Ethereum dan lainnya), bukan blockchain Layer 1 dengan mekanisme konsensus sendiri.

Execution Environment

EVM (Ethereum Virtual Machine) — protokol di-deploy sebagai smart contracts di jaringan berbasis EVM. Aave V3.3 di Aptos menggunakan Move VM, namun deployment utama berbasis EVM.

Programming Languages

Solidity — bahasa utama untuk smart contracts Aave di jaringan EVM.

Move — digunakan untuk deployment Aave V3.3 di Aptos.

TypeScript — digunakan untuk antarmuka dan query data.

JavaScript — digunakan untuk tooling dan integrasi.

Development Framework

Foundry: Framework pengembangan utama untuk Aave V4. Digunakan untuk kompilasi, testing, dan deployment.

Hardhat: Digunakan sebagai environment development untuk Aave V3, termasuk kompilasi, testing, dan deployment.

Docker Compose: Digunakan untuk development environment.

Node.js & Yarn: Untuk linting dan tooling.

Aave Address Book: Paket Solidity dan JavaScript untuk mengimpor alamat kontrak.

Security Model

V4 Security-First Framework: Model keamanan berlapis yang diterapkan sepanjang siklus pengembangan, bukan hanya sebagai tahap akhir sebelum deployment. Lima pilar utama: verifikasi formal untuk menguji kode secara matematis, review berlapis menggabungkan audit manual dan pengujian otomatis, pemeriksaan berkelanjutan pada setiap pembaruan kode, bug bounty berkelanjutan, dan alat AI untuk memindai jalur serangan yang tidak biasa.

Formal Verification: Certora terlibat sejak Maret 2025, bekerja sama dengan developer Aave Labs sejak tahap desain. Verifikasi formal berjalan paralel dengan penulisan kode.

Threat Modeling: Model ancaman formal dipelihara sebagai dokumen hidup sepanjang program, diperbarui seiring evolusi codebase. Trust assumptions antar komponen sistem didokumentasikan secara eksplisit dan dibagikan ke semua tim audit.

Invariant Testing: Dilakukan oleh Enigma Dark dan Trail of Bits pada periode September-November 2025.

Public Security Contest: Kontes keamanan publik enam pekan di Sherlock (November 2025-Januari 2026) dengan lebih dari 900 peneliti dan 950+ temuan.

Bug Bounty: Program bug bounty berkelanjutan untuk Aave V3 dan V4.
